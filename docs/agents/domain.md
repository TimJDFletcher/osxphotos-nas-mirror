# Domain docs

Single-context repo. Before exploring, read:

- `GLOSSARY.md`: the terms. Use them as defined in issue titles, tests, proposals and commit messages, and don't drift to the synonyms it lists under _Avoid_. A concept the glossary lacks is either invented language (reconsider) or a gap (note it for `/domain-modeling`).
- `docs/adr/`: read the ADRs that touch the area you're about to change.

If your output contradicts an ADR, say so explicitly rather than overriding it quietly:

> _Contradicts ADR 0004 (the share is a mirror), but worth reopening because…_
